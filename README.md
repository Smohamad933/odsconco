# شرکت مشاوران افق دانش ثریا

وب‌سایت شرکتی فارسی و راست‌به‌چپ به‌همراه پنل مدیریت محتوا، پیام‌رسان داخلی، ثبت حضور و غیاب و اتوماسیون گردش کارهای شرکت. پیاده‌سازی بدون فریم‌ورک و وابستگی Composer انجام شده تا روی PHP و IIS و پایگاه‌داده MySQL قابل نصب باشد.

## نیازمندی‌ها

- PHP 8.1 یا جدیدتر روی IIS (FastCGI)
- افزونه‌های PHP: `PDO`, `pdo_mysql`, `OpenSSL`, `JSON`
- MySQL 5.7+ یا MariaDB 10.4+ با پشتیبانی InnoDB و دیتابیس خالی برای نصب
- IIS با دسترسی **Modify** برای هویت Application Pool در پوشه `storage/`
- IIS URL Rewrite و PHP FastCGI؛ مسیر پیش‌فرض PHP در `web.config` برابر `C:\php\php-cgi.exe` است و در صورت تفاوت باید اصلاح شود.
- HTTPS برای دسترسی مکانی مرورگر و استفاده امن از حساب‌ها
- مرورگر به‌روز برای `IndexedDB`, `WebRTC` و Geolocation

برای نام کاربری/گذرواژه پیش‌فرضی در پروژه وجود ندارد.

## نصب روی IIS

1. PHP را روی Windows Server نصب کنید و در IIS به‌عنوان FastCGI Handler فعال کنید؛ مطمئن شوید نسخه‌ای که IIS اجرا می‌کند، `pdo_mysql` را بارگذاری کرده است. ماژول IIS URL Rewrite نیز باید نصب باشد.
2. این پوشه را به‌عنوان Physical Path سایت IIS انتخاب کنید؛ در همان پوشه باید `index.php` و `web.config` مستقیماً قرار داشته باشند. اگر ZIP را استخراج می‌کنید، فایل‌های داخل پوشه‌ی اصلی استخراج‌شده را مبنا قرار دهید، نه پوشه‌ی والد.
3. یک دیتابیس خالی MySQL و کاربر دارای دسترسی به آن در کنترل‌پنل هاست بسازید. در نصب اولیه، دسترسی ساخت جدول، ایندکس و تغییر جدول لازم است.
4. به هویت Application Pool همان سایت، دسترسی **Modify** روی `storage/` بدهید. این پوشه برای نگهداری امن تنظیمات اتصال دیتابیس است و با `web.config` از دسترسی مستقیم وب مسدود شده است.
5. سایت را با HTTPS منتشر کنید. برای نصب از راه دور، یک مقدار تصادفی قوی را موقتاً در متغیر محیطی `APP_SETUP_KEY` تعریف کنید؛ سپس `https://دامنه/setup.php` را باز کنید. در صفحه نصب، میزبان، پورت، نام دیتابیس، نام کاربری و گذرواژه MySQL را وارد کنید. نصب‌کننده اتصال را بررسی و جدول‌ها را ایجاد می‌کند؛ مرحله بعد حساب مدیر را می‌سازد. پس از نصب، `APP_SETUP_KEY` را حذف کنید. بدون این کلید، نصب فقط از خود سرور/localhost مجاز است.
6. صفحه‌های سایت تا پیش از تنظیم دیتابیس به `setup.php` هدایت می‌شوند. بعد از نصب، از پنل مدیریت کاربران داخلی را بسازید و متن‌ها، اطلاعات تماس و محتوا را تکمیل کنید. گذرواژه اولیه هر همکار باید از راه امن در اختیار او قرار بگیرد و در اولین ورود تغییر داده می‌شود.
7. برای تولید پیوند QR از نشانی صحیح سایت استفاده کنید. برنامه به‌صورت پیش‌فرض از Host درخواست استفاده می‌کند؛ پشت پراکسی یا دامنه خاص، متغیر محیطی `APP_BASE_URL` را مانند `https://example.com` تنظیم کنید.

### توسعه محلی

ابتدا یک دیتابیس خالی MySQL بسازید و افزونه `pdo_mysql` را فعال کنید. سپس با PHP نصب‌شده از ریشه پروژه اجرا کنید:

```bash
php -S 0.0.0.0:8000
```

صفحه `http://localhost:8000/setup.php` را باز کنید و نصب را کامل کنید؛ localhost برای نصب به `APP_SETUP_KEY` نیاز ندارد. برای آزمودن موقعیت مکانی و استقرار واقعی، از HTTPS استفاده کنید؛ مرورگرها Geolocation را به‌جز localhost روی اتصال امن فعال می‌کنند.

## بخش‌های سایت و پنل

- صفحات عمومی: خانه، درباره ما، آرشیو پروژه‌ها، خدمات و تماس با ما
- داستان شرکت، ارزش‌های محوری، هیئت‌مدیره، سایر همکاران، خدمات، پروژه‌ها، کارفرمایان و مقالات در پنل قابل ویرایش‌اند.
- پروژه‌ها، مقالات، اعضا و کارفرمایان تا زمان انتشار از دید عمومی پنهان می‌مانند. فهرست پروژه‌ها، کارفرمایان، مقالات و اعضای شرکت عمداً خالی است تا اطلاعات واقعی شرکت وارد شود.
- چهار حوزه خدمات اولیه به‌عنوان متن نمونه درج شده و از پنل قابل تغییر یا حذف‌اند.
- فرم تماس، پیام‌ها را در پایگاه‌داده ثبت می‌کند؛ مدیر یا سرپرست آن‌ها را از بخش «درخواست‌های تماس» پیگیری می‌کند.
- در مسیر `/setup.php` نصب دو مرحله دارد: آزمایش اتصال MySQL و ساخت جدول‌ها، سپس ساخت حساب نخستین مدیر. صفحه پس از ساخته‌شدن مدیر قفل می‌شود. ایجاد و غیرفعال‌سازی همکاران از پنل مدیریت انجام می‌شود.
- اتوماسیون داخلی برای ثبت درخواست/کار، ارجاع به مسئول، تعیین سررسید، یادداشت‌گذاری، ارسال برای بازبینی و تأیید یا بازگشت توسط مدیر در مسیر `/automation.php` قرار دارد. تمام تغییر وضعیت‌ها در تاریخچه ثبت می‌شوند و هر کارمند فقط درخواست‌های مربوط به خود را می‌بیند.

## طراحی پیام‌رسان هیبریدی

- متن پیام‌ها، شناسه کاربران و فراداده فایل (نام/اندازه/نوع) روی سرور ذخیره می‌شوند.
- فایل پیوست در IndexedDB مرورگر فرستنده نگهداری می‌شود؛ فایل حجیم به سرور PHP یا پوشه `storage/` آپلود نمی‌شود.
- با درخواست گیرنده، تب‌های هر دو کاربر با WebRTC تلاش می‌کنند فایل را مستقیم و با کانال داده رمزگذاری‌شده DTLS منتقل کنند. گیرنده فایل را در پوشه دانلود دستگاه خود دریافت می‌کند.
- هر دو طرف باید آنلاین باشند و گفت‌وگوی همان همکار را باز نگه دارند. پیاده‌سازی اولیه از STUN عمومی برای کشف مسیر استفاده می‌کند؛ برای شبکه‌های سازمانی، NAT سخت‌گیر یا پایداری عملیاتی، TURN اختصاصی و آزمون شبکه لازم است. **ارسال فایل در صورت شکست اتصال مستقیم، روی سرور ذخیره یا رله نمی‌شود.**
- فضای IndexedDB وابسته به مرورگر و دستگاه است و ممکن است با پاک‌کردن داده مرورگر حذف شود؛ برای نگهداری بلندمدت، فایل اصلی را جداگانه آرشیو کنید.
- پیام‌های متنی روی سرور به‌صورت متن قابل خواندن ذخیره می‌شوند و در این نسخه رمزنگاری سرتاسری (E2EE) ندارند. اطلاعات بسیار محرمانه را از این سامانه ارسال نکنید.

## حضور و غیاب و حریم خصوصی

- کارمند می‌تواند درخواست دستی، درخواست با QR محل شرکت یا درخواست دورکاری با موقعیت را ثبت کند.
- QR توسط مدیر/سرپرست ساخته می‌شود، ۹۰ ثانیه اعتبار دارد و برای هر کاربر در همان دوره یک‌بار قابل استفاده است. QR به‌تنهایی مانع اشتراک‌گذاری تصویر کد یا جعل حضور نیست.
- موقعیت مکانی فقط پس از انتخاب ثبت دورکاری و تأیید صریح کاربر، هنگام ثبت همان رویداد گرفته می‌شود؛ ردیابی پیوسته وجود ندارد. مختصات با دقت محدود ذخیره شده و فقط مدیران مجاز امکان دیدن آن را دارند.
- همه درخواست‌ها، از جمله QR و GPS، ابتدا «در انتظار تأیید» هستند. مدیر/سرپرست آن‌ها را تأیید یا رد می‌کند.
- GPS مرورگر قابل جعل است و دقت آن تضمین نمی‌شود؛ این نسخه جایگزین دستگاه حضور و غیاب تأییدشده یا سامانه حقوق و دستمزد نیست. پیش از استفاده سازمانی، سیاست نگهداری داده‌های مکانی، مدت حذف سوابق و الزامات حقوقی شرکت را مشخص کنید.

## داده و پشتیبان‌گیری

- اطلاعات اتصال MySQL در فایل خصوصی `storage/database.php` ذخیره می‌شود؛ این فایل در Git نادیده گرفته شده و پوشه `storage/` در IIS از دسترسی وب محافظت شده است. در صورت مدیریت اتصال با محیط سرور، متغیرهای `APP_DB_HOST`, `APP_DB_PORT`, `APP_DB_NAME`, `APP_DB_USER` و `APP_DB_PASSWORD` نیز پشتیبانی می‌شوند.
- کاربران، تنظیمات و محتوای سایت، پیام‌ها و فراداده فایل‌ها، سوابق حضور و اتوماسیون در MySQL ذخیره می‌شوند. خود فایل‌های حجیم چت روی سرور ذخیره نمی‌شوند.
- از دیتابیس MySQL در کنترل‌پنل هاست یا با ابزارهایی مانند `mysqldump` به‌صورت منظم نسخه پشتیبان بگیرید و دسترسی به آن را محدود کنید.
- نصب این نسخه دیتابیس SQLite قدیمی را به MySQL منتقل نمی‌کند؛ برای این نسخه‌ی تازه، اطلاعات جدید از طریق نصب‌کننده در MySQL ساخته می‌شوند. فایل‌های تنظیمات و پشتیبان دیتابیس را در مخزن عمومی یا بسته انتشار قرار ندهید.

## تکمیل اطلاعات لازم

برای آماده‌سازی نسخه نهایی، اطلاعات واقعی شرکت را در پنل وارد کنید: شماره تماس، شناسه و لینک بله/تلگرام، ساعات و نشانی دفتر، شرح خدمات دقیق، داستان و تاریخ شکل‌گیری، اسامی و رزومه هیئت‌مدیره، فهرست سایر اعضا، فهرست کارفرمایان، مقالات و مشخصات/تصاویر پروژه‌ها. اتوماسیون داخلی در این نسخه یک گردش کار عمومیِ درخواست، ارجاع، پیگیری و تأیید است؛ برای تبدیل آن به فرایندهای دقیق شرکت، نوع درخواست‌ها، زنجیره تأیید و مسئول هر مرحله را اعلام کنید.
